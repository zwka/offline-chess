# Branded Landing Page and Suite visual identity

Status: ready-for-agent
GitHub issue: https://github.com/zwka/offline-chess/issues/4

## Parent

https://github.com/zwka/offline-chess/issues/3

## What to build

Deliver the working four-Tool gallery in richer Ink & Brass, with the original Open board symbol beside Offline Chess and reusable visual assets for subsequent Tool slices. Establish the identity through a usable surface, not a standalone framework rewrite.

## Acceptance criteria

- [ ] All four Tools remain equally accessible in the gallery; no prescribed routine or activity dashboard is introduced.
- [ ] Refine the open geometric board frame, four inset squares, and separated corner detail; use symbol plus wordmark and coherent task-specific Tool icons rather than placeholder chess characters.
- [ ] Derive legible favicon, regular app, and maskable app icons; check small sizes and one-color reproduction.
- [ ] Use richer brass surfaces, serif major headings, and sans-serif functional text in both Themes; preserve shared Theme behavior and the dark default.
- [ ] Make the brand a link to the Landing Page. Do not add a Tool switcher to the Landing Page; inside-Tool switching belongs to its own ticket.
- [ ] Expose reusable visual assets without replacing the Tool frameworks or removing current functionality. Retain one manifest, one root service worker, current URLs, and existing saved data.
- [ ] Validate phone/desktop layout, keyboard/touch operation, focus, contrast, and representative screenshots with existing Suite browser tests; update branding expectations without weakening offline coverage.
- [ ] Record the parent spec's intentional expansion beyond the original integration-only functionality boundary in domain documentation, preserving the single-origin decision.

## Blocked by

None (can start immediately).
