# Branded Landing Page and Suite visual identity

Status: resolved
GitHub issue: https://github.com/zwka/offline-chess/issues/4

## Parent

https://github.com/zwka/offline-chess/issues/3

## What to build

Deliver the working four-Tool gallery in richer Ink & Brass, with the original Open board symbol beside Offline Chess and reusable visual assets for subsequent Tool slices. Establish the identity through a usable surface, not a standalone framework rewrite.

## Acceptance criteria

- [x] All four Tools remain equally accessible in the gallery; no prescribed routine or activity dashboard is introduced.
- [x] Refine the open geometric board frame, four inset squares, and separated corner detail; use symbol plus wordmark and coherent task-specific Tool icons rather than placeholder chess characters.
- [x] Derive legible favicon, regular app, and maskable app icons; check small sizes and one-color reproduction.
- [x] Use richer brass surfaces, serif major headings, and sans-serif functional text in both Themes; preserve shared Theme behavior and the dark default.
- [x] Make the brand a link to the Landing Page. Do not add a Tool switcher to the Landing Page; inside-Tool switching belongs to its own ticket.
- [x] Expose reusable visual assets without replacing the Tool frameworks or removing current functionality. Retain one manifest, one root service worker, current URLs, and existing saved data.
- [x] Validate phone/desktop layout, keyboard/touch operation, focus, contrast, and representative screenshots with existing Suite browser tests; update branding expectations without weakening offline coverage.
- [x] Record the parent spec's intentional expansion beyond the original integration-only functionality boundary in domain documentation, preserving the single-origin decision.

## Blocked by

None (can start immediately).

## Answer

Implemented the Ink & Brass four-Tool gallery with original Open board symbol/wordmark, four distinct task icons, brass header/icon/card treatment, serif major headings, sans functional text, dark-default/shared Theme, and linked brand. Tool frameworks, current URLs, storage, production chess-piece artwork, one manifest and root worker are unchanged.

Reusable interface and generation instructions: [visual identity](../../../docs/visual-identity.md). Assets are under `public/identity/`: shared CSS tokens, SVG symbol family, standalone and monochrome Open board. `npm run icons` derives existing Suite favicon/app/maskable PNG paths from the symbol. Later Tool slices can consume these without a dependency or framework change. Approved functionality expansion is recorded in [ADR-0001](../../../docs/adr/0001-single-origin-suite-with-transferred-sources.md#approved-ux-expansion), referencing the parent spec rather than duplicating it.
