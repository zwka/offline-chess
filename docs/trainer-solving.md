# Trainer Saved Activity and navigation

Trainer keeps Saved Activity in its existing IndexedDB Run records, not a second draft store. `loadTrainerData` validates records against their Puzzle Sets; a malformed Run does not hide a valid Library. `ActiveRun.currentPuzzleIndex`, `currentPuzzle`, and `results` retain the exact Puzzle, supplied-line move index, error/reveal/completion state, and retries. Existing schema/backup compatibility and scoring are unchanged.

Ordinary entry opens the Library. Each unfinished Run has a paused, informative Resume/Start fresh choice, including when multiple Puzzle Sets have active Runs. Only explicit Resume, Start new Run, or Generator's explicit Do Puzzles Handoff enters Solve. Handoff continues to reuse an existing active Run and bypass the ordinary entry choice. Start fresh confirms abandonment and uses `startRunAtomically`; cancellation or an aborted transaction retains the previous Run. Sets and completed history are not removed.

## Persistence and navigation seams

- `apps/woodpecker/apps/trainer/src/App.tsx`: `queueRunOperation` serializes actions, timer checkpoints, and starting/replacing Runs. `updateRun` applies a move/retry/reveal only after `saveRun` commits. Storage failures remain visible in an alert rather than being dismissed as successful saves.
- `prepareToNavigate` pauses/snapshots the selected active Run, opens the paused Library, commits the snapshot through that queue, and returns whether navigation may continue. It blocks navigation during an in-flight action or failed checkpoint. Later programmatic switchers/solution-study entry should await this function (or extract that same boundary) before changing location; do not navigate with a bare `location.assign` from an independent button.
- Ordinary same-window, same-origin anchor clicks anywhere in the document already use this boundary, including anchors a Suite switcher mounts outside React. Preserve normal anchor semantics; modifier-clicks, downloads, and new-tab links do not leave the current view and are not intercepted. Brand and Generator links use the same path. A later switcher should use plain same-origin anchors, without its own eager navigation handler.
- `use-active-run-timer.ts`: time is derived only from a visible Solve interval using `performance.now()`. `withActiveTime(run, true)` returns a paused snapshot for departure. One-second checkpoints and visibility/pagehide pauses supplement action saves; pagehide is not the only persistence path. Back/forward-cache restoration returns to the paused Library. Closed-Suite wall time is never reconstructed from a saved timestamp. Abrupt process termination can lose time since the last committed checkpoint, not add closed time.
- `storage.ts`: `saveActiveRunTime` updates only time on an existing active Run, never reviving an abandoned/completed Run. Keep this narrow write to avoid overwriting move progress with stale timer snapshots. `startRunAtomically` abandons only the same Puzzle Set's active Run. Future Reader review must be outside `view === "solve"`; return with the existing Run ID, never create a replacement Run or reinterpret its results.

- [Puzzle Solution Study](puzzle-solution-study.md) awaits `prepareToNavigate`, then leaves Trainer entirely. Explicit Return loads the same Run/Puzzle IDs, with `reviewPaused` excluding the returned Solve workspace from the timer until **Resume solving**. Completed/advanced origins open existing Run history without rewinding progress. No Reader code writes Run state.

The demo-seeded localStorage flag is optional metadata: denied access cannot prevent opening valid IndexedDB content. Unavailable IndexedDB is reported honestly; Trainer does not pretend to keep a durable in-memory Run. Browser eviction, deletion, or a failed write cannot be promised away; existing backup export remains available when saved content can be opened.
