# Puzzle Solution Study (#14)

Trainer exposes **Study solution** only for a completed Puzzle Result (including completion after error) or an explicitly revealed Puzzle, including historical revealed Puzzles after Next. An incorrect move alone is insufficient. Completed/earlier Puzzles can be selected from Run history or the completed Run summary. Viewing the supplied line cannot change scoring or award a point for a revealed/failed Puzzle. Alternate accepted mate-in-one moves do not replace the recorded source line.

Revelation is additive optional `solutionRevealed` metadata on a failed Puzzle Result, independent of its eventual completion and scoring. It survives Next, abandonment, persistence, and backup. Retry still re-locks the current unfinished Puzzle. Existing schema-v1/v2 Runs remain readable: a known current `solution-revealed` state is normalized to the marker on load. Old skipped Failures without that evidence remain locked; guessing whether they were revealed would expose wrong-move-only Puzzles. No score or Active Solving Time is recomputed.

`apps/woodpecker/apps/trainer/src/solution-study.ts` applies the source's first/setup move to its FEN, creates a new chess.js game at that resulting position, and legally plays **all** remaining moves before serializing PGN. This retains side to move, fullmove counters, castling/en-passant rights, and promotions. It does not serialize a suffix against the original pre-setup FEN, or start at the player's later reveal position.

Trainer's `studySolution` awaits the existing `prepareToNavigate` Run checkpoint before writing its separate context and leaving. The versioned localStorage record `offline-chess.reader.solution-study.v1` contains stable Run/Set/Puzzle IDs, Puzzle index, supplied PGN, exact source FEN/moves identity, and Reader position (path/FEN/orientation). No normal Study bookmark or Library source is written. Failed writes leave a visible explanation and the paused Trainer Library available.

`/pgn-reader/?solution=1` opens a labeled separate view using `renderMobileReader` and the existing hydration, notation, board, keyboard, and touch controls. Its `solution-study.ts` adapter invokes the shared read-only origin verifier, checks the origin/content identity and completion/reveal gate, then renders. It never creates/resumes/scores/saves a Run. Retry re-locks an unfinished Puzzle; a retained context cannot bypass that gate. Missing/deleted/changed origins, corrupt metadata, or unavailable storage produce an explanation with ordinary Reader and Trainer Library links, not a blank view or replacement Run.

`shared/solution-study.js` owns the v1 context key, codec and position validation, source-line identity, eligibility rule, and narrow read-only Trainer origin verification. Trainer's storage boundary shares its database/store identifiers; Reader no longer knows the database layout or duplicates scoring-state gates. The plain ESM module plus TypeScript declarations works with both existing builds: Vite bundles it for Trainer; Reader's mobile build copies it alongside its emitted adapter and rewrites that one import. Suite precaching discovers the copied module normally. This keeps independent Reader verification without adding a storage framework or importing Trainer's write-capable runtime.

The solution's position saves synchronously after each move/flip. Reload or reopening its URL restores it; ordinary Reader Library also offers **Resume Puzzle Solution Study** when a context exists. Ordinary PGN study keeps its independent Resume/Start fresh choice and restores its exact source, game, move, variation, and orientation. Solution playback does not insert Library content or use an engine.

**Return to Trainer** uses `/woodpecker-trainer/?solutionRun=<Run ID>&puzzle=<Puzzle ID>`. The existing Run is loaded, never replaced. If that Puzzle is still current, its Solve workspace opens paused with **Resume solving**; Puzzle-changing controls remain disabled until explicit Resume. For an already advanced/completed Run it opens that Run's history without rewinding progress or changing its current Puzzle. Missing origins leave ordinary Library navigation with an explanation. Reviewing in Reader, reload/reopening, and paused return do not accrue Active Solving Time.
